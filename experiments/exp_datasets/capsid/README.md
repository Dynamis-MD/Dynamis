# HIV-1 Capsid (PDB 3J3Q)

The full HIV-1 capsid cryo-EM structure — a **real, non-synthetic ~2.4 M-atom**
system used as the large-scale end-to-end Dynamis benchmark (partitioning, halo
exchange, LJ forces, Langevin NVT across many GPUs).

| File | Atoms | Extent (Å) | Description |
|------|------:|-----------|-------------|
| `3j3q_capsid.xyz`        | 2,440,800 | ~767 × 1077 × 798 | Full capsid, heavy atoms only |
| `3j3q_capsid_sub350.xyz` |   175,218 | 350³ cube         | Dense shell chunk (mid-scale) |
| `3j3q_capsid_sub150.xyz` |    33,212 | 150³ cube         | Dense shell chunk (small, 2-GPU repro) |

The two `sub*` files are **nested** axis-aligned cube cut-outs (sub150 ⊂ sub350)
sharing one lower corner on a **dense region of the capsid shell** (the interior
is hollow) — handy smaller stand-ins that keep the real chemistry. They are
regenerated by `07_retrieve_hiv.py --subsets` and pinned in
`scripts/checksums.txt`.

## Provenance & reproducibility

Heavy atoms only — hydrogens are absent from the 3J3Q cryo-EM structure and are
**not** added here (a production run with a real NNP would need proper H
placement). The full capsid is a deterministic parse of the RCSB mmCIF, so it is
byte-reproducible as long as RCSB does not re-version the entry:

```bash
python scripts/07_retrieve_hiv.py            # download 3J3Q.cif.gz from RCSB -> 3j3q_capsid.xyz
python scripts/07_retrieve_hiv.py --subsets  # re-cut the sub150 / sub350 shell cubes
```

Because that download is ~40 MB and the parse takes a minute, all three files
are also shipped in the hosted archive (`download_datasets.sh`) and cached in the
Delta shared directory — no RCSB round-trip needed on the cluster.

## Notes

- No box in the file: the loader (`setup_system.load_capsid_from_xyz`) sizes a
  cubic cell as `max_extent + 2 × 20 Å` and draws Maxwell–Boltzmann velocities
  at 310 K with centre-of-mass drift removed.
- LJ (UFF, Rappe et al. 1992) is a placeholder potential; bonded pairs are
  excluded by a `< 2.2 Å` distance threshold.
